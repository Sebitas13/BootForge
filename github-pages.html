Publica tu sitio en GitHub Pages

Del repositorio local a una URL con HTTPS. Sin servidores, sin tarjeta y sin configuración rara.

En esta guía

  • 1. Prepara el repositorio
  • 2. Activa Pages
  • 3. Revisa la URL
  • 4. Errores clásicos
  • 5. Dominio propio
  • 6. Checklist final

1. Prepara el repositorio

Necesitas una cuenta de GitHub y Git instalado. Crea un repositorio público sin README ni licencia si ya tienes esos archivos en local; así evitas el primer conflicto.

git init
git add .
git commit -m "Mi primer sitio con Bootstrap"
git branch -M main
git remote add origin https://github.com/TU-USUARIO/TU-REPO.git
git push -u origin main

Tu entrada debe ser index.html

GitHub Pages busca index.html en la raíz (o en la carpeta que configures). Si tu archivo principal tiene otro nombre, renómbralo o crea un redirect.

2. Activa GitHub Pages

  1. 1

    Abre Settings → Pages

    En el repositorio, entra en Settings y busca Pages en la barra lateral.

  2. 2

    Elige la fuente

    Selecciona Deploy from a branch, rama main y carpeta / (root). Guarda.

  3. 3

    Espera el deploy

    GitHub tarda uno o dos minutos. La URL aparece en la misma pantalla: https://TU-USUARIO.github.io/TU-REPO/.

Si prefieres un flujo reproducible, usa GitHub Actions con actions/configure-pages, upload-pages-artifact y deploy-pages. En Settings → Pages → Source elige GitHub Actions.

# .nojekyll
# Desactiva el procesamiento de Jekyll. Útil si tu sitio es HTML estático.
# Crea el archivo vacío en la raíz del repositorio.

3. Revisa la URL publicada

No basta con que la página de inicio cargue. Abre la consola del navegador y revisa:

  • No hay errores 404 de CSS, JS, imágenes o fuentes.
  • Los enlaces internos funcionan y respetan mayúsculas y minúsculas.
  • El sitio se ve bien en móvil y en escritorio.
  • La consola no muestra errores de JavaScript.
  • El favicon y los metadatos sociales cargan correctamente.

4. Errores clásicos (y cómo evitarlos)

Problemas frecuentes al publicar en GitHub Pages
SíntomaCausa probableSolución
La página se ve sin estilosRuta con mayúsculas distintas o ruta absoluta /assets/...Usa rutas relativas y copia el nombre exacto de la carpeta.
404 al entrar a una rutaNo existe el archivo o el enlace tiene un errorRevisa el enlace y añade un 404.html en la raíz.
El sitio tarda en actualizarseCaché del navegador o deploy en colaEspera un minuto, recarga con Ctrl + F5 y revisa Actions.
La página principal no apareceFalta index.html o está en otra carpetaColócalo en la raíz o ajusta la carpeta de publicación.
Enlaces a localhostQuedaron URLs de desarrolloBusca localhost y 127.0.0.1 antes de publicar.

5. Dominio propio (opcional)

Si tienes un dominio, puedes apuntarlo a GitHub Pages. Añade un archivo CNAME en la raíz con tu dominio y configura los registros DNS que indica GitHub. Después activa Enforce HTTPS.

El CNAME no es magia

Si cambias el dominio, actualiza también las URLs canónicas, el sitemap y las etiquetas Open Graph. Un dominio mal configurado puede dejar el sitio inaccesible durante horas.

6. Checklist final

  • index.html existe en la raíz y tiene un title único.
  • No hay enlaces rotos ni recursos 404 en la consola.
  • El sitio funciona a 360px, 768px y 1440px.
  • Puedes navegar con Tab y el foco siempre es visible.
  • Las imágenes tienen alt y dimensiones declaradas.
  • El repositorio tiene README, licencia y descripción.
  • HTTPS está activo y no hay contenido mixto.
  • Probaste la URL publicada en un dispositivo real.
